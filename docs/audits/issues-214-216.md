## Confirmed failures and fixes

Baseline `npm test`: seven failures. The recurring delete button lacked `btn-danger`; the import map/CSP stamp was stale; five assertions expected different formatting, escaping, warning counts or absence of explanatory prose. Escaping was already safe (`<` is escaped); corrected expectations without weakening script-injection rejection. Retained the actual calculation and warning assertions.

Baseline GitHub [Checks run 42149472938](https://github.com/luizfds/wealth-planner/actions/runs/42149472938) incorrectly succeeded: the tests job log records **seven failures**, but `npm run coverage | tee coverage.txt` ran under `bash -e` without pipefail. This PR explicitly selects `shell: bash`, which enables `-e -o pipefail`. [Release run 42149472990](https://github.com/luizfds/wealth-planner/actions/runs/42149472990) failed in Bump, stamp and test (six failures after the automatic stamp); commit/tag/push and rebuild steps were skipped. No release workflow was rerun during this audit.

## Privacy, accessibility and release readiness

Rule data and spending insights remain local. Existing optional AI/sync/price integrations remain opt-in paths with their own controls; the app's whole CSP permits these services and therefore is not a claim of universal network isolation. Existing synthetic tests check AI allowlists, explicit consent, escaping and CSV handling. No external financial-service integration or real account was exercised.

Native buttons and details are used for new actions. Setup and report regions have accessible names. The comparison table retains row/column headers and keyboard scrolling. Mobile controls and overflow are measured by the page script. Desktop and mobile screenshots are synthetic. These checks do not replace manual testing with an actual screen reader or an iOS/Android device.

**Audited main is not release ready**: its release failed and its apparent green Checks status hides failures. The consolidated branch is a release candidate only after all five corrected CI jobs pass and review is complete. Keep the PR draft and all three issues open until main can be rechecked. The repository releases and requests a Pages rebuild automatically on merge, so merging also crosses the deployment boundary: explicit owner approval is required before either action. Do not rerun Release, tag, merge or deploy as part of this audit.
